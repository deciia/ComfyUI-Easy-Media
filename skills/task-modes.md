# 任务模式选择（T2V / 图生 / 首尾帧 / 参考生 / 编辑 / 直通）

本包回答一个问题：**这一段的画面，应该用哪种生成方式？** 判断依据只有两个——手里有什么素材、这段要"守住"什么。

## 1. 六种模式一览

| task_mode | 界面名 | 吃什么素材 | 守住什么 | 放开什么 |
|---|---|---|---|---|
| `default`（无图） | T2V 文生视频 | 只要文字 | 什么都不锁 | 全部由描述决定 |
| `default`（1 图） | I2V 图生视频 | 1 张图＝**首帧** | 起始画面（构图/人物姿态/光线） | 之后的发展 |
| `l2v` | L2V 尾帧 | 恰好 1 张＝**尾帧** | 结束画面 | 如何到达这一帧 |
| `fmlf2v`（多帧） | FMLF2V 首尾帧 | 2 张＝首帧＋尾帧 | 起点与终点 | 中间过程 |
| `ref` | R2V 参考生视频 | 1–9 图 + 可选 1 视频/1 音频 | 主体外观/场景风格/音色 | 构图、动作、镜头 |
| `edit` | VI2V 视频编辑 | 1–9 图 + 源视频 | 未指定的部分一律保留 | 指定的局部改动 |
| `passthrough` | Pass 直通 | 不需要 | 不生成，直接过 | — |

> 关键区别：**I2V 是"从这张图开始演"，R2V 是"照着这些参考演"**。给错模式，参考图会被当成首帧或干脆被忽略。

## 2. 决策顺序（按顺序问，命中即停）

1. **这段是否复用现成视频？** → `passthrough`
2. **是否要在已有视频上改东西（换人/换景/改字/换台词）？** → `edit`（VI2V）
3. **是否只给了结束画面（或只要落点一致）？** → `l2v`
4. **是否首帧和尾帧都指定了（转场、变身、开门、昼夜切换）？** → `fmlf2v`
5. **是否只有一张"必须从它开始"的画面？** → `default`（I2V，首帧）
6. **是否有主体/场景/音色的参考素材，但构图动作要重新设计？** → `ref`（R2V）**——大多数叙事段都属于这一类**
7. **什么都没有，纯描述？** → `default`（T2V）

## 3. 各模式优点与适用场景

### T2V（default，无图）
- 优点：最自由，镜头/构图/表演完全按描述走；不受素材画质拖累。
- 适合：空镜、氛围镜头、转场、概念演示、无法拍到或不需要固定的画面。
- 代价：**人物/车辆/场景每次都不一样**，跨段不连续；重要主体容易前后不一致。
- 结论：只在"这段不需要守住任何身份"时用。

### I2V（default，1 图＝首帧）
- 优点：首帧 100% 可控，起手画面稳，最容易与上一段做接续（上一段末帧直接当首帧）。
- 适合：**连续性镜头的主力**（context 衔接）、产品展示开场、必须精确对齐上一镜的画面。
- 代价：图里没有的东西模型不敢加；构图被首帧锁死，机位变化受限。
- 结论：段与段要"无缝接上"时首选。

### L2V（l2v，1 图＝尾帧）
- 优点：能精确控制"落点"（结尾停在哪一帧），适合做钩子收尾、广告落版、转场前定帧。
- 适合：要收在特定画面（举起零件、门关上、字幕位留白）、倒推演法。
- 代价：起点不受控，过程容易跑偏；不适合要求全程稳定的叙事。
- 结论：只在"结尾必须精准"时用。

### FMLF2V（多帧，首帧＋尾帧）
- 优点：起点终点都锁，中间由模型补，能做出"变化类"镜头（变身、开箱、从白天到夜晚）。
- 适合：转场设计、状态变化、两镜头之间的桥接、变身/变形/生长。
- 代价：中间过程不可控，动作幅度大时容易崩；两端不匹配会明显跳。
- 结论：明确有 A→B 两端时用，别拿它当普通叙事段。

### R2V（ref，参考图/视频/音频）——**大部分情况**
- 优点：能锁身份（人物/车/设备）与风格/音色，同时保留构图与动作自由；最像"导演讲戏+演员自己演"。
- 适合：叙事主体段、口播、产品细节、人物出镜、需要跨段一致的所有镜头。
- 代价：参考给太多会僵化（每段建议 ≤3 张）；冲突的参考会互相打架；写不清"每张图管什么"就会变成随机拼贴。
- 用法要点：**在 retention_analysis 里逐张写清用途**（外观/场景/风格/音色），并说明"不复制什么"。
- 结论：只要这段有"不能变的人或物"，就用 R2V。

### VI2V（edit，视频编辑）
- 优点：保留原视频的表演、节奏、运镜，只改指定部分，最省重拍成本。
- 适合：换服装/换车牌/去掉水印/换背景/改台词/局部特效。
- 代价：**没写"要保留"的地方可能被一起改掉**；改动范围越大越容易崩。
- 用法要点：必须成对写"改什么＋保什么"，越具体越好。
- 结论：二次修改、修片、合规处理时用。

### Pass（passthrough）
- 优点：跳过生成，直接进合成。
- 适合：已有成片片段、片头片尾、静帧、占位。
- 代价：不产生新内容。

## 4. 与衔接（shot / context / context_drift）的配合

| 衔接 | 含义 | 配合模式 |
|---|---|---|
| `shot` | 独立切镜 | T2V、R2V |
| `context` | 承接上一段末帧继续演 | **I2V 最稳**；R2V 也可（靠上下文 latent） |
| `context_drift` | 允许跳变（换场/换时间） | T2V、R2V |

> 只要用了 `context`，优先考虑 I2V（把上一段末帧当首帧），连续性最好。

## 5. 判断时的自检清单（必须逐段回答）

1. 这段有没有**不能变的人/物**？有 → R2V。
2. 这段是不是**必须从上一段末帧接着演**？是 → 衔接 context + I2V。
3. 这段是不是**结尾必须停在某个画面**？是 → L2V。
4. 这段是不是**首尾都要定、中间变化**？是 → FMLF2V。
5. 这段是不是**在改一条已有视频**？是 → VI2V。
6. 以上都不是，且不需要守住身份 → T2V。
7. 这段不用生成 → Pass。

## 6. 常见错误

- **有参考图却给了 T2V**：参考被完全忽略，最常见的"图白生成了"。
- **把场景参考升成主体**：主体越多，模型越僵；场景一致性交给 context，而不是造主体。
- **一段塞 5 张参考**：互相冲突，画面开始拼贴；建议 ≤3。
- **用 I2V 却想要自由构图**：首帧会锁死构图，机位变化会崩。
- **用 L2V 演全程**：起点失控，适合收尾不适合叙事。
- **edit 只写改什么、不写保什么**：模型会把周围一起重画。

## 7. 写进 set_task_modes 的格式

```
set_task_modes
{
  "items": [
    { "index": 1, "task_mode": "ref",  "context_mode": "shot",
      "reason": "有老赵四视图+零件盘，需锁身份与道具；独立开场" },
    { "index": 2, "task_mode": "default", "context_mode": "context",
      "reason": "承接段1末帧继续下坠，首帧即上一段末帧" },
    { "index": 3, "task_mode": "fmlf2v", "context_mode": "shot",
      "reason": "从静止到破水，起止两端都定" }
  ]
}
```

逐段写原因，不要整片一刀切。
